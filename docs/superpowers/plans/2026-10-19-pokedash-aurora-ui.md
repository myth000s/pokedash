# pokedash Aurora UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the deal feed into the dark "Aurora Dashboard". It gets real CardTrader pictures, a best-deal hero chosen by biggest € saving, a stats row and holo hover effects.

**Architecture:** Four tasks.
1. The data layer stores a validated CardTrader picture link per listing.
2. The feed is re-sorted by € saving, and a small `getFeedStats` query is added.
3. A dark theme with new fonts, a top bar, a stats row, a skeleton and the error page form the page shell.
4. The deal presentation splits into `HeroDeal`, `DealTile` and a client `CardImage` with a placeholder fallback.

Effects are CSS-only and are switched off under `prefers-reduced-motion`.

**Tech Stack:** Next.js 16.4.2 (App Router, `cacheComponents`), React 19, Tailwind CSS v4, Drizzle + Postgres (PGlite in tests), Vitest 5 + Testing Library, `next/font/google`.

**Spec:** `docs/superpowers/specs/2026-10-19-pokedash-aurora-ui-design.md` (and its mockup `docs/superpowers/specs/assets/2026-10-19-aurora-desktop-mockup.html`). It builds on `docs/superpowers/specs/2026-10-19-pokedash-design.md`.

**Branch:** work on `feat/aurora-ui`. Create it from `main` after slice 1 is merged, or from `feat/slice-1` if it isn't merged yet.

## Global Constraints

- Next.js 16.4.2 with `cacheComponents: true`. Request-time data stays inside `<Suspense>` with `await connection()`. Read the relevant guides in `node_modules/next/dist/docs/` before touching pages, fonts or images.
- Tailwind CSS v4. Design tokens go in `src/app/globals.css` under `@theme`.
- Dark only. The token values, verbatim:
  - page `#080a17`, with radial glows: cyan `#4cc9f0` (~28%) top-left, purple `#b15cff` (~30%) top-right, pink `#f85888` (~22%) bottom
  - panel `rgba(255,255,255,.06)`, border `rgba(255,255,255,.13)`
  - text `#e9ecff`, muted `#a9b1e0`
  - gold `#ffd166`, mint `#06d6a0`
  - CTA gradient `#ffd166 → #f8a14a`
  - holo conic `#4cc9f0, #b15cff, #f85888, #ffd166, #06d6a0`
- Fonts: Russo One (headings and big numbers) and Chakra Petch (body), loaded with `next/font/google`. They replace Geist.
- Every animation (holo border, picture tilt and foil, live-dot pulse) stops under `@media (prefers-reduced-motion: reduce)`.
- Accessibility: WCAG AA contrast, visible focus rings, links and buttons at least 44 px tall, picture `alt` = product name, savings always carry text, no emoji icons.
- No official Pokémon logos or branding. The wordmark is the text "pokedash".
- Pictures are plain lazy `<img>` tags pointing at CardTrader. They are not passed through `next/image` (decision: CardTrader previews are already small, and this avoids proxying and test friction). Disable `@next/next/no-img-element` on that one line, with a comment saying why.
- `src/app/layout.tsx` keeps `suppressHydrationWarning` on `<html>`.
- The money (integer cents), ID-only matching and secrets rules from slice 1 still apply. Never open or print `.env.local`.
- Tests: Vitest, with DB tests on in-memory PGlite and real migrations. No test touches the network. Commit with explicit paths, never `git add -A`.

## Review Focus

1. A picture that fails to load (404, blocked) should switch to the placeholder without shifting the layout. Test: Task 4 `falls back to the placeholder when the picture fails to load`.
2. A picture link from anywhere but CardTrader over https must never be stored or rendered. Test: Task 1 `rejects unsafe picture links`.
3. Exactly one deal: show only the hero, with no empty "All deals" section. Test: Task 4 `shows only the hero when there is one deal`.
4. A fresh database (nothing ingested) gives stats of 0 and "–" instead of crashing. Tests: Task 2 `returns zeros and nulls for an empty database` and Task 3 `shows dashes when nothing is known yet`.
5. Listings and products from another set are not counted in the stats. Test: Task 2 `ignores products and listings from other sets`.
